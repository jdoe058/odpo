# Timetable

## Требования

- Python 3.12+
- pip

## База данных

Проект использует **SQLite** — встроенную базу данных Python. 
Отдельный сервер БД (PostgreSQL, MySQL) устанавливать не нужно.

Файл базы создаётся автоматически при первой миграции:
`python manage.py migrate` → появится `db.sqlite3` в корне проекта.

Для резервной копии достаточно скопировать этот файл:
`cp db.sqlite3 db.backup.sqlite3`

Если в будущем потребуется PostgreSQL — измените блок `DATABASES` 
в `odpo/settings.py` и установите `psycopg2-binary`.

## Возможности

- Просмотр расписания занятий с фильтрами (база, цикл, период).
- **Экспорт документов в DOCX.** Виды выгрузок описаны в реестре
  `timetable.exports.kinds` и наполняются в `apps.ready()`:

  |  Код             | Документ             |
  |------------------|----------------------|
  | `schedule`       | Расписание занятий   |
  | `teacher_load`   | Распределение часов  |
  | `timesheet`      | Табель               |

  Шаблоны `.docx` загружаются через страницу **«Шаблоны»** (пункт
  в шапке, доступен авторизованным). Поддерживается drag&drop и
  выбор файла через диалог. Рабочим считается **последний загруженный**
  шаблон для вида; старые версии остаются в БД и доступны для
  скачивания, но в выгрузке не участвуют. Валидация `.docx` — по
  формату zip и читаемости через `docxtpl`.
- Разграничение доступа: расписание, шаблоны и экспорт доступны
  только после входа.
- **Контроль нагрузки сотрудников.** У каждой должности заданы лимиты
  `max_hours_per_day`, `max_hours_per_week` и `max_hours_per_year`
  (пустое значение = лимит не задан). Учебный год считается
  с 1 сентября по 31 августа. Неделя — календарная, Пн–Вс.

  Проверка выполняется в трёх точках:
  - при **импорте** расписания из XLSX — если превышение обнаружено,
    цикл не создаётся, в БД ничего не записывается;
  - при **правке** занятия через фронт — форма возвращается с
    сообщениями об ошибках, занятие не сохраняется;
  - на странице **расписания** — блок «Переработки» показывает
    фактические превышения, сгруппированные по масштабу и сотруднику.

  В штатном режиме блок «Переработки» пуст: данные попадают в БД
  только через валидируемые пути. Непустой блок означает, что
  переработку внёс администратор через админку в обход проверки —
  Django admin для этого остаётся осознанным escape hatch.

  Бизнес-логика собрана в `timetable/services/limits.py`:
  `find_violations` (валидация до записи) и `calculate_overtime`
  (постфактум-мониторинг для UI). Раскладка «преподаватели × дни»
  для шаблона — `timetable/services/grid.py`.

### Демо-данные

`timetable/demo_data.py` — вымышленные базы, сотрудники, названия
циклов и занятия. Загружаются командой `seed_demo`. Все значения
не пересекаются с реальными: базы названы «УЧЕБНЫЙ КОРПУС №1» и т.п.,
сотрудники — условные ФИО, названия циклов — типовые программы ДПО.

## Запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/jdoe058/odpo odpo
cd odpo
```

### 2. Создать и активировать виртуальное окружение

**Windows:**

```powershell
python -m venv venv
venv\Scripts\activate
```

если политика включена
```
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
```

**Linux / macOS:**

```bash
python -m venv venv
source venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать `.env`

Скопируйте `.env.example` в `.env` и заполните:

```
SECRET_KEY=your-secret-key-here
DEBUG=True
```

### 5. Применить миграции

```bash
python manage.py migrate
```

### 6. Заполнить справочники

```bash
python manage.py seed_references
```

Команда создаёт виды финансирования, должности, типы занятий и
копирует эталонные .docx-шаблоны из `timetable/exports/seed_templates/`
в медиахранилище. Если шаблон для какого-то вида уже загружен —
он не перезаписывается.

Полезные флаги:

```bash
python manage.py seed_references --dry-run
python manage.py seed_references --only=funding,positions
python manage.py seed_references --only=templates
```

> **Внимание.** `seed_references` использует `get_or_create` и
> существующие должности не перезаписывает. Если БД была засеяна
> до появления недельных и годовых лимитов, лимиты
> `max_hours_per_week` / `max_hours_per_year` нужно проставить
> в админке вручную (или удалить старые должности и запустить
> команду заново).

### 6a. (Опционально) Загрузить демо-данные

Для быстрого наполнения стенда вымышленными базами, сотрудниками,
циклами и занятиями:

```bash
python manage.py seed_demo
```

### 7. Создать суперпользователя

```bash
python manage.py createsuperuser
```

### 8. Запустить сервер

```bash
python manage.py runserver
```

Открыть в браузере:

- Расписание: http://127.0.0.1:8000/
- Шаблоны: http://127.0.0.1:8000/templates/
- Админка: http://127.0.0.1:8000/admin/

### 8a. Запустить сервер на определённом порту, например 8081

```bash
python manage.py runserver 8081
```

Открыть в браузере:

- Расписание: http://127.0.0.1:8081/
- Шаблоны: http://127.0.0.1:8081/templates/
- Админка: http://127.0.0.1:8081/admin/


## Шаблоны документов

Управление шаблонами — на странице **«Шаблоны»**
(`/templates/`, ссылка в шапке сайта). Там же:

- форма загрузки нового `.docx` (drag&drop или выбор через диалог);
- список всех версий по каждому виду — с указанием даты, автора,
  комментария и ссылкой на скачивание;
- кнопка «Удалить» для каждой версии.

Файлы физически лежат в `media/templates_docx/<kind>/`. Рабочим
считается **последний загруженный** шаблон для данного `kind` —
при экспорте используется именно он. Если нужно вернуться к
предыдущей версии, удалите свежую запись, и «рабочим» станет
предыдущий по дате загрузки.

Любой шаблон может рассчитывать на общий набор переменных, который
формируется в `timetable.exports.kinds.build_common_context`:

- `cycle_name`, `funding`, `base`, `start`, `end`
- `signer`, `signer_position`
- `approver`, `approver_position`

Плюс поля, специфичные для конкретной выгрузки (см.
`build_own_context` в `timetable/exports/<kind>.py`).


## Тесты

```bash
python manage.py test timetable
```

Пакет `timetable/tests/`:

- `_factories.py` — общие фабрики для тестов (генерация .docx,
  создание моделей справочников).
- `test_exports_base.py` — рендер docx через `docxtpl` и формирование
  HTTP-ответа (`render_docx`, `docx_response`).
- `test_exports_kinds.py` — реестр выгрузок (`register`, `get`,
  `all_specs`, `codes`) и сборка общего контекста.
- `test_exports_library.py` — выбор рабочего шаблона
  (`get_latest_template`), статус по видам (`template_status`),
  копирование эталонных шаблонов (`seed_templates`).
- `test_exports_models.py` — `DocumentTemplate`: путь загрузки,
  валидация `.docx` в `clean()`.
- `test_exports_views.py` — `export_view`: доступ, 404, happy path
  по каждому виду.
- `test_grid.py` — раскладка «преподаватели × дни» (`calculate_grid`).
- `test_limits.py` — `find_violations` (день / неделя / учебный год,
  границы, исключения цикла и конкретных занятий) и
  `calculate_overtime` (постфактум-мониторинг).

## Технический долг

Известные слабые места, которые осознанно отложены. Не блокируют
работу, но требуют внимания при развитии проекта.

- **Drop-зона на странице шаблонов.** Файл принимается и
  отправляется корректно, но UX неполный:
  - нет ссылки «Убрать» — чтобы сбросить выбранный файл,
    нужно перезагрузить страницу;
  - стандартное сообщение Dropzone (`.dz-message`) скрыто,
    показывается свой текст; при обновлении библиотеки стоит
    перепроверить, что поведение не изменилось;
  - если выбранный файл не проходит валидацию на клиенте
    (например, слишком большой), Dropzone показывает
    английские тексты — `dictFileTooBig` и подобные
    переведены частично.
- **Медиа-файлы шаблонов открыты анонимам.** `{{ tpl.file.url }}`
  ведёт на `/media/templates_docx/...` без проверки прав —
  любой, кто знает URL, скачает файл. Для внутренних шаблонов
  риск низкий (внутри placeholder'ы), но при развитии проекта
  стоит закрыть: либо через `django.views.static.serve` с
  `@login_required`, либо через view-обёртку, либо через
  продакшн-веб-сервер с авторизацией.
- **`timetable/exports/registry.py`** — предположительно мёртвый
  код (дубликат `kinds.py` со старыми полями `label`, `view`,
  `url_slug`). Не импортируется, не участвует в экспорте.
  Перед удалением — проверить `grep` по всему репозиторию.
- **Разграничение прав для методистов.** Сейчас страница
  «Шаблоны» доступна любому авторизованному пользователю.
  Когда появится группа «методисты» — перевести на
  `@user_passes_test` или Django-разрешения.
- **Учебный год в лимитах.** Границы зафиксированы как
  1 сентября — 31 августа в `services/periods.py`. Если в
  организации учебный год начинается иначе — потребуется
  настройка (setting или поле в Position/Organization).
